# 附录 A 术语表（中英对照）

本表收录全书反复出现的核心术语。“首次出现”指该术语首次被系统讲解的章节，而不是字符串第一次出现的章节。正文中的译名与释义以本表为准；如果发现前后不一致，欢迎反馈。

术语表是初稿，会随着章节写作持续补充。对于业界尚未形成统一中文译名的词（如 Harness、Rollout），本书保留英文，并在首次出现时给出解释性翻译。

## A.2 基础概念

| 术语 | English | 释义 | 首次出现 |
|---|---|---|---|
| 智能体 | Agent | 能围绕目标自主决定下一步动作、调用工具并根据观察调整行为的软件系统 | 第 1 章 |
| Agent Harness | Agent Harness | 包在模型之外、负责循环控制、工具执行、上下文管理、权限与观测的工程层 | 第 1 章 |
| 脚手架 | Scaffolding | 为提升模型在特定任务上的表现而搭建的辅助结构；与 Harness 高度重叠，但更强调任务特化与临时性 | 第 1 章 |
| 薄 Harness / 厚 Harness | Thin / Thick Harness | 以模型自主决策为主、约束较少为薄；把流程、校验与安全边界显式写入代码为厚 | 第 1 章 |
| 神谕上下文测试 | Oracle Context Test | 由人提供完成任务所需的精确上下文，用于区分模型能力失败与 Harness 失败 | 第 1 章 |
| 仓库地图 | Repo Map | 从代码结构生成定义与引用关系图，在 token 预算内选择上下文片段 | 第 1 章 |
| 编辑格式 | Edit Format | 模型输出可校验的修改块，由 Harness 解析并应用到文件 | 第 1 章 |
| 任务 | Task | 用户或上游系统交付的一个目标，从接收目标到产出最终结果 | 第 2 章 |
| 智能体主循环 | Agent Loop | “组装上下文 → 调用模型 → 执行工具 → 回填结果”的重复过程 | 第 2 章 |
| 轮 | Turn | 一次模型调用及其触发的工具执行与结果回填 | 第 2 章 |
| 步 | Step | 循环中的一次原子动作，可以是一次模型调用或一次工具执行 | 第 2 章 |
| 停止条件 | Stop Condition | 决定循环退出的判据，例如没有工具调用、达到步数或成本预算、命中终止信号 | 第 2 章 |
| 循环终止原因 | Loop Stop Reason | Harness 决定循环退出的类型化原因，如自然完成、预算耗尽、无进展、取消 | 第 2 章 |
| 外部验证 | External Verification | 由独立于模型的检查器验证完成声明，如测试、类型检查、Schema 校验 | 第 2 章 |
| 预算分配 | Budget Allocation | 把任务总预算拆分到轮次、工具调用与单次观察，先分配再消费 | 第 2 章 |
| 状态机 | State Machine | 用有限状态和迁移规则描述执行流程，使每个退出路径都有明确原因 | 第 2 章 |
| 无进展检测 | No-progress Detection | 比较连续动作与观察是否重复，判断循环是否陷入空转 | 第 2 章 |
| 协作取消 | Cooperative Cancellation | 通过取消令牌在安全点停止新动作，并依赖工具配合中断正在执行的操作 | 第 2 章 |
| 轨迹 | Trajectory | 一次任务执行中完整的消息、工具调用、结果与状态变化序列 | 第 2 章 |
| 执行采样 | Rollout | 从给定输入开始的一次完整执行，常用于评测与强化学习 | 第 15 章 |
| 会话 | Session | 一次连续交互的边界，包含消息历史与相关状态 | 第 2 章 |
| 系统提示词 | System Prompt | 位于对话最前方、用于设定角色、约束与工作方式的指令 | 第 6 章 |
| ReAct | ReAct | 交替生成推理（Reasoning）与动作（Acting）的提示与执行范式 | 第 1 章 |

## A.3 模型与协议

| 术语 | English | 释义 | 首次出现 |
|---|---|---|---|
| Token | Token | 模型处理文本的基本单位，通常小于一个词；上下文长度与费用均以 token 计 | 第 1 章 |
| 用量 | Usage | 厂商返回的输入、输出、缓存与推理 token 统计，用于预算与计费 | 第 3 章 |
| 模型提供方 | Provider | 提供模型推理服务的厂商或平台 | 第 3 章 |
| 函数调用 | Function Calling | 厂商 API 提供的机制：模型按给定 JSON Schema 返回结构化调用请求 | 第 3 章 |
| 工具调用 | Tool Use | 模型调用外部工具的通用能力，涵盖函数调用、内置工具与 MCP 工具 | 第 3 章 |
| 原生工具调用 | Native Tool Calling | 厂商 API 直接返回结构化工具名与参数的机制，Harness 无需从自由文本中解析动作 | 第 3 章 |
| 模型接入层 | Provider Abstraction | 屏蔽不同厂商在请求格式、流式事件、工具协议与错误码上的差异的适配层 | 第 3 章 |
| 响应结束原因 | Finish Reason | 模型单次响应结束的原因，例如自然结束、达到长度上限、请求工具调用或内容过滤；取值因厂商而异 | 第 3 章 |
| 提供方事件 | Provider Event | 适配器归一化后的流式事件，如文本增量、工具调用参数增量、响应结束 | 第 3 章 |
| 结构化输出 | Structured Output | 通过 JSON Schema 或语法约束模型输出格式 | 第 3 章 |
| 流式输出 | Streaming | 以增量事件返回文本与工具调用参数，降低首字延迟并支持中断 | 第 3 章 |
| 并行工具调用 | Parallel Tool Calls | 模型在单轮中返回多个互不依赖的工具调用请求 | 第 3 章 |
| 扩展思考 | Extended Thinking | 部分模型在最终回答前生成内部推理内容；可见性、预算与计费方式因厂商而异 | 第 3 章 |

## A.4 工具与 MCP

| 术语 | English | 释义 | 首次出现 |
|---|---|---|---|
| 工具 Schema | Tool Schema | 描述工具名称、用途与参数的结构化定义，是模型选择工具与填充参数的依据 | 第 5 章 |
| 工具结果 | Tool Result | 工具执行后回填给模型的内容，通常包含成功标志、输出与错误信息 | 第 5 章 |
| 工具执行器 | Tool Executor | Harness 中负责参数校验、权限检查、实际执行与结果格式化的模块 | 第 5 章 |
| 工具注册表 | Tool Registry | 集中登记工具定义、处理器与策略元数据，并在启动时校验一致性的模块 | 第 5 章 |
| 参数校验 | Argument Validation | 在执行前按工具 Schema 子集检查模型给出的参数，失败时转成可行动的观察 | 第 5 章 |
| 并行安全 | Parallel Safety | 工具声明自己无副作用、可与其他调用并发执行；默认只允许只读工具声明 | 第 5 章 |
| 工具风险等级 | Tool Risk Level | 工具注册时声明的副作用等级：read、write、destructive、external | 第 5 章 |
| 截断 | Truncation | 结果超过预算时按行或字符裁剪，并显式标记、给出续读方式 | 第 5 章 |
| 工具命名空间 | Tool Namespace | 用固定前缀区分不同来源的同名工具，例如 mcp__server__tool | 第 5 章 |
| 幂等 | Idempotency | 同一操作重复执行不产生额外副作用；对写文件、发请求等动作尤其重要 | 第 5 章 |
| MCP | Model Context Protocol | 一个开放协议，用标准方式向模型客户端暴露工具、资源与提示 | 第 5 章 |
| MCP 客户端 | MCP Client | 发起 MCP 连接、发现并调用服务器能力的一方，通常位于 Harness 内 | 第 5 章 |
| MCP 服务器 | MCP Server | 通过 MCP 暴露工具、资源或提示的服务进程 | 第 5 章 |
| MCP 资源 | MCP Resource | 服务器暴露的可读数据，由客户端决定何时读取并放入上下文 | 第 5 章 |
| MCP 提示 | MCP Prompt | 服务器提供的可复用提示模板，客户端可将其转为用户消息 | 第 5 章 |
| MCP 采样 | MCP Sampling | 服务器请求客户端代为调用模型的机制；支持程度依客户端与服务器实现而定 | 第 5 章 |
| 传输层 | Transport | MCP 的通信方式，常见为本地 stdio 与基于 HTTP 的远程传输 | 第 5 章 |

## A.5 上下文与记忆

| 术语 | English | 释义 | 首次出现 |
|---|---|---|---|
| 上下文窗口 | Context Window | 单次模型调用可接受的最大 token 数，包含输入与输出 | 第 6 章 |
| 上下文工程 | Context Engineering | 有意识地选择、排序、压缩与刷新进入上下文的信息，使模型在每一步都拿到最相关的内容 | 第 6 章 |
| 上下文预算 | Context Budget | 单次调用可分配给固定前缀、历史与工具结果的输入 token 上限，先扣除输出预留与安全边际 | 第 6 章 |
| Token 估算 | Token Estimation | 用字符数、CJK 比例等启发式方法近似 token 数，并用厂商 usage 持续校准 | 第 6 章 |
| 外置 | Externalization | 把超长内容写入工作区文件，上下文只保留预览与路径，需要时再分段读取 | 第 6 章 |
| 上下文压缩 | Context Compaction | 上下文接近窗口上限时，把较早的历史压缩为摘要或结构化状态 | 第 6 章 |
| 摘要 | Summarization | 用模型或规则把长内容改写为更短、保留关键信息的版本 | 第 6 章 |
| 渐进式披露 | Progressive Disclosure | 先给索引或概要，按需再加载细节，避免一次性灌满上下文 | 第 6 章 |
| 上下文腐化 | Context Rot | 输入变长后，模型对中段信息注意力下降、指令遵循变差的工程现象 | 第 6 章 |
| 记忆 | Memory | 跨任务可复用的知识、偏好与经验；与当前执行状态相对 | 第 7 章 |
| 工作记忆 | Working Memory | 当前任务内需要持续维护的临时状态，例如计划、已改文件与待验证项 | 第 7 章 |
| 长期记忆 | Long-term Memory | 跨会话保留的知识、偏好与经验，通常需要显式写入与检索 | 第 7 章 |
| 任务状态 | Task State | 描述当前任务目标、约束、待办、已改文件、验证结果与未决调用的结构化数据 | 第 7 章 |
| 会话状态 | Session State | 描述一次会话的工作区、模型、权限档、审批与预算消耗的状态 | 第 7 章 |
| 状态块 | State Block | 把任务状态渲染成供模型阅读的紧凑文本，受上下文预算约束 | 第 7 章 |
| 检查点 | Checkpoint | 可恢复的状态快照，包含任务/会话状态、文件变更与未决调用，用于中断后续跑或回滚 | 第 7 章 |
| 状态 | State | Agent 在某一时刻需要持久化的全部信息，不等同于消息历史 | 第 7 章 |
| 事件日志 | Event Log | 只追加、不修改的执行事件记录，可按序重放以重建状态与审计 | 第 7 章 |
| 状态快照 | State Snapshot | 某一事件序号上的完整状态副本，用于加速恢复 | 第 7 章 |
| 恢复 | Recovery | 从快照与事件日志重建状态、对账未决调用并继续执行的过程 | 第 7 章 |
| 恢复对账 | Reconciliation | 恢复时核对未决工具调用与实际副作用，决定重试、标记已提交或结果未知 | 第 7 章 |
| 工作区漂移 | Workspace Drift | 状态记录的文件与磁盘实际内容不一致，通常由外部修改或删除导致 | 第 7 章 |
| 有效一次 | Effectively-once | 通过至少一次执行、幂等去重与对账，使外部副作用在结果上只发生一次 | 第 7 章 |
| 幂等键 | Idempotency Key | 由会话、调用与参数生成的稳定标识，重复执行时用于去重 | 第 7 章 |
| 记忆污染 | Memory Poisoning | 把不可信内容或错误推断写入长期记忆，持续影响后续行为 | 第 7 章 |
| 项目记忆文件 | Project Memory File | 放在仓库中的持久指令文件，例如 CLAUDE.md、AGENTS.md，用于承载项目约定 | 第 7 章 |

## A.6 规划与多智能体

## A.7 执行环境与安全

| 出站策略 | Egress Policy | 控制沙箱可以访问哪些网络目标的策略 | 第 10 章 |
